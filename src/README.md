- `bybit/adapter.py` 从 `bybit/bybit-1.1.2.zip` 展开后修改。
- `gate/adapter.py` 从 `gate/gate-1.2.2.zip` 展开后修改。

- `registry.json`、现有 ZIP 和可信签名者记录保持原样。

## 本轮行为

1. Gate 现货按 `page`、永续按 `offset` 拉完同一固定时间窗口后全局按成交时间排序；历史补同步也复用此路径。兼容永续仅有秒级 `create_time`、成交 ID 为 `trade_id` 的响应。
2. Gate 在拉取、解析、有效性检查和 `emit` 完成后推进轮询水位；初次请求失败也保留开始位置。重复页、缺少 ID、无效时间或分页超安全上限会报错，不宣称同步完成。
3. Bybit 在 execution 订阅成功后、读取实时成交前执行 REST 补拉，保留订阅确认前收到的 execution。后台 heartbeat 在补拉期间继续运行。
4. Bybit 先收集全部游标页，再按成交时间全局排序。重复游标、冲突 ID、缺少列表或无效成交不视为成功。
5. Bybit 进程启动回看最近七天；进程内断线保留恢复位置，长时间断线按每段最多七天查询。所有分类成功推送后才推进该段恢复位置。

## 离线验证

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

测试只回放模拟响应。`adapters.base.AdapterBase` 由测试替身提供，实际桥接层不在本仓库内，因此通过测试不代表持久队列、去重、仓位归并、数据库或在线更新已通过验收。

## 边界

- `emit` 返回仅表示桥接层接受了调用，不证明数据库已经落盘；发布前必须核对实际确认语义。
- REST 与 WebSocket 重叠会重复推送成交，依赖桥接层按交易所、账户、市场、成交 ID 去重。不同订单的独立成交不得合并去重。
- Bybit 启动的七天回看不能保证找回更早停机缺口；永久恢复位置仍应由桥接层数据库提供。REST 迟到记录也需要周期对账。
- Gate 本轮只修复既有 REST 回退和手动历史同步路径；未增加正常 WebSocket 连接时的持续 REST 对账，进程重启仍需历史补同步。
- Gate 超过 100000 偏移的窗口会明确失败，需缩小补同步范围；此版本没有自动递归拆窗。
- 同一毫秒成交使用确定性次序，无法据此证明真实撮合次序；桥接层应保留原始数据并支持重算。
- 历史成交没有历史杠杆/保证金快照，不用当前仓位填充旧历史。
- 本轮没有修改止损识别、手续费符号或 HTTP 429/5xx 策略；后续事项见审查记录。

正式发布必须由本地受信任签名流程重新生成 manifest 文件哈希和签名、ZIP SHA-256，再更新注册表。不要提交签名私钥。
